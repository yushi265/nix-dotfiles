# Inbox Tidy Skill

## 概要

このスキルはObsidian vaultの `00_Inbox/`（新規メモの一時置き場）に溜まったノートを整理する。各ノートを読んで内容を判定し、トピックタグを付与し、必要ならリネームし、フロントマターを補完したうえで `20_Notes/` 直下へ振り分ける。Inboxを常に空に近い状態に保つためのワークフロー。

設計思想は「フォルダで分類せず、タグ（プロパティ）で分類する」Obsidian流。`20_Notes/` はフラットに保ち、分類はタグで行う。一覧は `20_Notes/ノート一覧.base` の「📥 Inbox（要処理）」「🗂 トピック別」ビューで俯瞰できる。

## 動的コンテキスト収集

まず以下を実行してInboxの状態を把握する:

```
!`ls -1 00_Inbox/ 2>/dev/null`
```

Inboxが空なら「Inboxは空やで、整理するもんないわ」と伝えて終了する。

## ステップ1: 引数解析

- 引数なし: Inbox内の全ノートを対象に、提案 → 確認 → 実行の順で進める
- `--auto` / `--yes`: 確認をスキップして一気に実行する
- ファイル名・キーワード指定: 該当するノートだけを対象にする

## ステップ2: Inboxのノート収集

`00_Inbox/` 直下の `.md` ファイルを列挙する。各ファイルについて以下を読む:

- フロントマターの有無（先頭が `---` か）
- 既存の `created` と `tags`
- 本文の冒頭〜要点（タグ判定に十分な範囲）

## ステップ3: 各ノートの分析

各ノートについて 3 つを決める。

### 3-1. トピックタグの判定

以下の語彙から該当するものを選ぶ。複数該当すればすべて付ける。

| タグ | 範囲 |
|------|------|
| `tech` | 技術・開発・プログラミング・プロンプト・ツール調査 |
| `money` | お金・税金・保険・投資・各種手続き |
| `life` | 暮らし・買い物・旅行・趣味・雑事 |
| `health` | 健康・筋トレ・食事・睡眠 |
| `idea` | アイデア・方法論・考察・思索メモ |

判定ルール:
- タグは小文字英語のベタ書き（vaultのクリッピング流儀に合わせる）
- 既存タグ（`coleta` 等のプロジェクトタグや `#todo`）は消さずに残す。トピックタグを先頭に追加する
- 上記のどれにも当てはまらない場合は、内容に即した新しいタグ（小文字英語）を提案する。勝手に確定せず提案として挙げる
- 内容が薄くて判定不能なものは `inbox` タグのまま残し、ユーザーに確認する

### 3-2. リネーム判定

以下に該当する場合は、本文から簡潔で分かりやすい日本語タイトルを提案する:
- `無題のファイル` / `Untitled` / 自動生成名
- 日付のみの名前（`YYYY-MM-DD`）で、内容が日記・ログでないもの

既に内容を表す分かりやすいタイトルならそのまま維持する。リネームはあくまで提案で、確定はユーザー確認後。

### 3-3. フロントマター補完

- FMなし → `created`（`stat -f '%SB' -t '%Y-%m-%d' <file>` で取得したファイル作成日）と `tags` を付与する
- `tags: []` → トピックタグのブロック形式に置換する
- 既存tagsブロックあり → トピックタグを先頭行に追記する

tagsはブロック形式（`tags:` の下に `  - xxx`）で統一する。

## ステップ4: 振り分け提案の提示

`--auto` でない場合、ここで一旦止めて提案テーブルを提示する:

| ノート | 付けるタグ | リネーム案 | 移動先 |
|--------|-----------|-----------|--------|
| 例.md | tech | （変更なし） | 20_Notes/ |

ユーザーに「これで振り分けてええ？」と確認する。修正要望があれば反映する。

## ステップ5: 実行

確認OK（または `--auto`）なら、ノートごとに:

1. フロントマターを Edit で更新（タグ付与・補完）
2. 必要ならリネーム（`mv` でファイル名変更）
3. `20_Notes/` 直下へ移動（`mv "00_Inbox/<name>" "20_Notes/<name>"`）

注意:
- 移動先に同名ファイルがある場合は上書きせず、` 2` 等のサフィックスを付けるかユーザーに確認する
- Templater構文や既存の日本語表記は壊さない
- Edit前にファイルをReadしてから編集する（Editツールの制約）

## ステップ6: 結果サマリ

処理したノートを一覧で報告する:

```
✅ Inbox整理完了（N件）
- tech: ファイルA, ファイルB
- money: ファイルC
...
📥 Inbox残り: M件（判定不能で保留したもの）
```

`20_Notes/ノート一覧.base` の「🗂 トピック別」ビューで結果を確認できることを案内する。

## 注意事項

- `00_Inbox/` はルート直下にある（`00_Journals` の上に表示される）
- 新規ノートの保存先は `.obsidian/app.json` の `newFileFolderPath: 00_Inbox` で設定済み
- このVaultはobsidian-gitが30秒間隔で自動コミットするため、整理結果は自動でバックアップされる
- 確定していない判定は憶測で進めず、ユーザーに確認すること
