# コードレビューモード

成果物はレビューコメント。**コードは変更しない**（修正依頼が続く場合は別タスクとして扱う）。

## 着手前に揃える情報

| 情報 | 欠けていたら |
|------|-------------|
| 対象（PR番号 / ブランチ / diff / ファイル） | ユーザーに確認。未指定で作業ツリーに差分があればそれを対象と宣言 |
| 変更の意図 | PR説明・コミットメッセージ・会話から読み取る |
| 重点観点 | 指定が無ければ全観点を標準の深さで |
| レビューの深さ（軽く / 通常 / 徹底的に) | 未指定なら「通常」と宣言 |

## 作業手順

1. まず変更の意図を把握し、diff 全体を通読する
2. 変更されたコードだけでなく、**その呼び出し元・影響先も読む**（diff の外に壊れるものがないか）
3. 以下の観点で確認する:
   - **正しさ**: ロジックの誤り、境界値、null/空/異常系、並行処理、リソースリーク
   - **セキュリティ**: 入力検証、インジェクション、秘密情報のハードコード、権限チェック
   - **テスト**: 新しい振る舞いにテストがあるか、テストが実質を検証しているか（形だけのテストでないか）
   - **設計**: 既存パターンとの整合、不要な複雑さ、変更の波及範囲
   - **可読性**: 命名、コメントの過不足
4. 指摘には**重大度**を付ける: [CRITICAL] 本番障害・脆弱性 / [HIGH] バグの可能性が高い / [MEDIUM] 改善すべき / [LOW] 好みの範囲
5. **確信が持てない指摘は「要確認」と明示する**。憶測で断定しない。指摘には根拠（該当行・具体的な失敗シナリオ）を添える
6. 良い点も1〜2個挙げる（何が守られているかの確認になる）

## 完了条件

- [ ] すべての指摘に重大度・該当箇所・根拠（具体的な失敗シナリオ）がある
- [ ] diff の外側（呼び出し元）への影響を確認した
- [ ] 修正必須（CRITICAL/HIGH）と任意（MEDIUM/LOW）が区別されている
- [ ] 指摘ゼロの場合も「何を確認した上で問題なしと判断したか」を報告した
- [ ] コードを変更していない
