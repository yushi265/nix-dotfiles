# バグ修正モード

**修正を依頼された場合のテンプレート。** 問題の報告・質問だけなら investigation として原因診断までにとどめ、修正はユーザーが求めてから。

**緊急時（本番障害等）の例外**: 影響を止める暫定対処（ロールバック・機能フラグオフ・切り戻し）の提案を最優先し、恒久修正は状況が落ち着いてから本手順で行う。暫定対処も本番への操作なので実施前に確認を取る（§0）。

## 着手前に揃える情報

| 情報 | 欠けていたら |
|------|-------------|
| 症状（何が起きるか） | ユーザーに確認（これが無いと作業できない） |
| 期待動作（本来どうあるべきか） | テスト・ドキュメント・類似機能から推定し宣言。仕様判断になるなら確認 |
| 再現手順 | 自分で再現を試みる。エラーログ・コードから再現条件を構築する |
| エラーログ / スタックトレース | 実行して自分で採取する |
| 変更してよい範囲 | 原因特定後、影響範囲から自分で提案 |

## 作業手順

1. **再現**: まずバグを再現する（テストまたは実行で）。**再現せずに修正に入らない。** 再現できない場合は、試したことを報告して指示を待つ
2. **原因特定**: 症状から逆に辿る。**「原因は X で、なぜなら Y」と1文で説明できる状態になるまで修正しない**
3. **回帰テスト**: バグを検出する失敗テストを先に書き、修正前に失敗することを確認する
4. **最小修正**: 原因そのものを直す。症状を隠す対症療法（条件分岐の追加、try/catch での回避）にしない
5. **検証**: 回帰テストが通ること + 既存テストがすべて通ることを確認する
6. **水平展開**: 同種のバグが他の箇所にないか検索する。あれば**修正せず**報告に含める
7. 完了報告（結果 / 変更点 / 検証 / 未検証・仮定・提案）

## 完了条件

- [ ] 原因を1文で説明した（「なぜ起きたか」が報告に含まれている）
- [ ] 修正前に失敗し、修正後に通る回帰テストがある
- [ ] 既存テストがすべて通った（実行出力を提示）
- [ ] 差分は原因の修正に必要な最小限
- [ ] 同種バグの有無を確認した
