# 既存コード調査モード

成果物は調査レポート。**コードは変更しない。**

## 着手前に揃える情報

| 情報 | 欠けていたら |
|------|-------------|
| 調べたいこと（質問） | ユーザーに確認（これが無いと作業できない） |
| 背景（なぜ知りたいか） | 会話から推定し宣言（報告の焦点が決まる） |
| 範囲（リポジトリ/ディレクトリ） | リポジトリ全体を既定とし、調査しながら絞る |
| 深さ（概要 / 実装詳細 / 影響範囲の完全列挙） | 背景から推定して宣言。未指定なら「実装詳細まで」 |

## 作業手順

1. 質問を「答えるべき小さい問い」に分解して提示する
2. **外から内へ読む**: README・設定ファイル → ディレクトリ構造 → エントリポイント → 対象領域を検索で特定 → 中心ファイルを読む → 呼び出し元/先を辿る → **テストで期待仕様を確認する**
3. **事実と推測を区別して記録する**: コードで確認できたこと（ファイル:行番号付き）と、状況からの推測を分ける
4. 動作確認が可能なら実際に動かして仮説を検証する
5. レポートを作成する:
   - **結論**: 質問への直接の答え（最初に書く）
   - **詳細**: 根拠となるコードの説明（すべて ファイルパス:行番号 付き）
   - **流れ**: 処理が複雑なら箇条書きで流れを示す
   - **問題なしと確認した観点**: 何を見て問題なし・該当なしと判断したか（結論が「無い・大丈夫」のときほど重要）
   - **未解決・未確認範囲**: 調べても分からなかったこと、時間・情報不足で見ていないこと
6. 重要な調査結果は `50_Investigations/` または当日のデイリーノートへの記録を提案する

## スケールする場合

- 対象が大きい場合（リポジトリ全体・文書群全体の監査など）は、**範囲別＋横断観点別の2軸**で並列エージェントに分割する（手順は [delegation.md](delegation.md) の「並列ファンアウト」）
- 発見した**矛盾は自分で正を決めない**: 対立の構図（AはX、BはY）＋自分の推奨を添えて、番号付きでまとめて人間に裁定を求める

## 完了条件

- [ ] 質問に直接答えている（周辺情報だけで終わっていない）
- [ ] すべての事実に出典（ファイルパス:行番号）がある
- [ ] 事実と推測が明確に区別されている
- [ ] 分からなかったことが「分からなかった」と正直に書かれている
- [ ] コードを一切変更していない
