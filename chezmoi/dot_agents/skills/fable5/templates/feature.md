# 新機能実装モード

## 着手前に揃える情報

| 情報 | 欠けていたら |
|------|-------------|
| 機能概要（何を作るか） | ユーザーに確認（これが無いと作業できない） |
| 目的（誰が・何のために使うか） | 会話・vault・チケットから推定し、解釈を宣言。判断つかなければ確認 |
| 期待する振る舞い（入力→出力の具体例を最低1つ） | 例が無ければ自分で例を作って提示し、認識を合わせる |
| 対象範囲（変更してよいファイル/ディレクトリ） | コードベースを調査して計画時に提示 |
| 制約（ライブラリ、規約、性能要件） | CLAUDE.md・lint設定・既存コードから調べる |
| 完了の定義 | 要求チェックリストから自分で定義して宣言 |

## 作業手順

1. 依頼を**要求チェックリスト**に変換して提示する
2. **類似機能の既存実装を探して読み**、このプロジェクトの実装パターン（命名・層構造・エラー処理・テストスタイル）を特定する
3. テスト・ビルドの実行方法を確認し、**現状がグリーンであることを確認**する
4. 計画（変更ファイル・手順・テスト方針）を提示し、そのまま着手する
5. **テストファーストで進める**: 失敗するテストを書く(RED) → 最小実装で通す(GREEN) → 整理する(REFACTOR)。このサイクルを小さく回す
6. 全テスト・lint・ビルドを実行する
7. 完了報告（結果 / 変更点 / 検証 / 未検証・仮定・提案）

## 完了条件

- [ ] 要求チェックリストの全項目に対応した
- [ ] 新しい振る舞いすべてにテストがあり、全テストが通った（実行出力を提示）
- [ ] 既存実装のパターンに沿っている（独自流儀を持ち込んでいない）
- [ ] 頼んでいない変更が差分に含まれていない
- [ ] 未検証事項・仮定が明示されている
