# AI-DLC / プロトタイプ実装モード

**検証用の使い捨てコードであり、本番品質は求めない。** ただし「省略しないこと」は守る。

## 着手前に揃える情報

| 情報 | 欠けていたら |
|------|-------------|
| 検証したい仮説（何を確かめたいか） | ユーザーに確認（これが無いとプロトタイプの意味がない） |
| 動けばよい範囲（ハッピーパスの定義） | 仮説から最小の形を自分で定義し、着手前に宣言 |
| 技術スタック | 最速で動くものを選び、選定理由を添える |
| 期限感 / サイズ感 | 未指定なら「最短で仮説検証できる最小構成」と宣言 |

## 品質トレードオフ（プロトタイプ特約）

- **省略してよい**: 網羅的テスト、エラーハンドリングの作り込み、性能最適化、リファクタリング、edge case 対応
- **省略しないこと**:
  - 動作確認（検証したいことが実際に検証できる状態にする。これが唯一の完了条件）
  - 秘密情報の管理（プロトタイプでも API キーのハードコード禁止）
  - 検証コアのスモークテスト1本（仮説検証の中心部分だけは自動で動作確認できるように）
  - 「本番化する場合の負債リスト」の作成

## 作業手順

1. 検証したい仮説を確認し、**「動いたと言える最小の形」を定義して提示**する
2. 最短経路で動くものを作る。設計の綺麗さより速度を優先し、迷ったら単純な方を選ぶ
3. ハッピーパスを**実際に動かして確認**する
4. 完了報告に以下を必ず含める:
   - **起動・確認手順**（人間が自分で動かせるように）
   - **仮説に対する所見**（検証できたこと・できなかったこと）
   - **負債リスト**: 本番化する場合に作り直すべき箇所（省略したエラー処理、ハードコード、テスト不足など）

## 完了条件

- [ ] 検証したいことが実際に動作確認できる（起動手順を提示）
- [ ] 仮説に対する所見が報告されている
- [ ] 負債リストがあり、「これは本番品質ではない」ことが明記されている
- [ ] 秘密情報がハードコードされていない
